# 14｜AWS：追踪 coding agent 的跨任务想法

- 论文：[arXiv:2610.11450](https://arxiv.org/abs/2610.11450)；[官方 PDF](https://arxiv.org/pdf/2610.11450)；[本地 PDF](14-AWS-ARC-thoughts.pdf)。主分类 cs.AI，2026-10-09 公告批次 New submissions；首次提交 2026-10-08（UTC），v1。
- 作者/机构（PDF 首页）：Chen Wu、Josh Passenger、Yin Song；AWS。
- 机构优先级：A+；标签：agent memory、continual learning、trace analysis；相关性：直接；novelty：高。

## 1. 做了什么

论文把 agent 写入脚本或笔记的信念、规则和计划当作可追踪“想法”，在 ARC-AGI-3 连续关卡中观察这些外部记忆何时创建、修正、丢弃或复用。

## 2. 怎么做、实验如何设计

冻结基础模型与 harness，跨轮次仅保留文件和完整行动日志；agent 用 Python/shell 探索无说明的互动任务。作者追踪七次运行、三种主干、两个模型家族中的脚本引用与笔记修改，而非仅以最终成功率推断学习机制。

## 3. 结论

直接证据：630 次脚本引用中只有 33 次跨任务边界；关卡切换前写的脚本有 74% 被弃用，常通过重写保留通用规则、丢掉当前关卡状态。笔记只追加不修订，矛盾靠日志裁决；错误硬编码状态是高成本失败。此结果是给定 harness 的观察性分析。

## 4. 未来影响

我的推断：程序性记忆应显式区分可迁移规则与环境瞬态值，并有主动修订或撤销机制，而不仅自动追加总结。

## 5. Critical thinking

关键假设是写入文件的东西足以代表 agent 的实际内部状态；未写出的潜在表征不可观察。与黑箱任务成功率研究相比，它更可解释但样本仅七次。建议复制到多种编码 agent、随机任务顺序与可编辑笔记条件，直接干预“保留/删除/重写”策略并测未来任务成功。

## 6. 可信度判断

**3/5**。白盒文件与日志让描述性发现可核查；因果解释受运行数、任务域与仅观察文件的限制。
