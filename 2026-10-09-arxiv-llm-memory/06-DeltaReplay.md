# 06｜DeltaReplay：按任务差异重用 GUI agent 记忆

- 论文：[arXiv:2610.11707](https://arxiv.org/abs/2610.11707)；[官方 PDF](https://arxiv.org/pdf/2610.11707)；[本地 PDF](06-DeltaReplay.pdf)。主分类 cs.AI，2026-10-09 公告批次 New submissions；首次提交 2026-10-08（UTC），v1。
- 作者/机构（PDF 首页）：Yudong Bai、Yihong Chen、Quanming Yao、Yaqing Wang；清华大学。
- 机构优先级：S；标签：agent memory、trajectory reuse、mobile GUI；相关性：直接；novelty：高。

## 1. 做了什么

论文解决“历史轨迹只部分吻合新任务”时强用记忆会误导、不用又浪费经验的问题。其核心不是扩大记忆库，而是逐步决定是否照做、换参数后做或交回基础 agent。

## 2. 怎么做、实验如何设计

成功轨迹存为页面/动作转换图；动作分解为任务无关操作和任务特定参数，再结合当前页面状态、任务目标做三路路由。实验在 AndroidWorld 与 SPA-Bench 同主干比较有/无记忆，按覆盖程度分层，并消融页面验证、参数重绑定等部件。全文还给出单步迁移安全的充分条件，但该定理依赖状态与动作映射一致性。

## 3. 结论

直接证据：相对同主干基础 agent，任务成功率最高分别增加 10.3 和 25.0 个百分点；部分无相关记忆任务并未观察到明显退化。论文的配对测试、覆盖分层与消融比仅报整体均值更有说服力；“最高提升”不等于所有设置均如此。

## 4. 未来影响

我的推断：这套“检索后先判断可迁移粒度”的路由可移植到网页自动化和程序性 agent memory，减轻旧案例对新任务的负迁移。

## 5. Critical thinking

关键假设是界面语义状态可可靠匹配、操作参数可安全替换；动态网页、权限弹窗、相似按钮或不可逆操作会破坏。与简单检索后复播不同，其改进在任务相对的局部转移判断。建议对 UI 改版、危险动作及恶意历史轨迹做压力测试，报告路由错误矩阵和每成功任务的额外计算成本。

## 6. 可信度判断

**4/5**。多基准、同主干对照、分层与消融以及明确条件化理论构成较强证据；真实移动应用长期变动和高风险操作仍未充分覆盖。
