## 1. 做了什么

论文提出长周期 agent 应先能持续运行而不丢失任务线程，再谈 continual learning。架构由不同时间尺度的 levels、每次自主推进的 ticks 和更强模型的 cascaded review/escalation 构成。各层保存有界文件，低层细节汇总至高层；持久文件保存操作知识、决策与待解问题，模型权重无需更新。

## 2. 怎么做，实验如何设计

tick 开始读取 checkpoint、standing decisions、计划、未知事项与任务卡，完成动作后写回；新 journal 记录覆盖旧状态。worker 通过任务 brief、进度汇报与指令契约协作，较强模型在评审失败时升级，关键负面发现要求保留。作者报告一次十日 RL 复现实验 campaign，211 ticks、47 次 context reset、403 次常规模型 worker 与 35 次强模型 worker，约 40 次实验、30 次 review、7 个关键发现。人类每日参与，九次主要决定；论文已有训练案例只是阅读对象，不授权本任务启动任何 GPU 工作。

## 3. 结论

案例支持架构在这次 campaign 中跨 reset 保持线程，早期写入操作知识改变后续行为。十个日历日的持续科研也体现文件记忆可超越一次模型上下文。但没有等预算 flat-file、无层级或不同升级机制的严格基线，因此不能断言其可靠性已普遍优于其他 harness；更不能把案例中的“没有遗忘”解释成对任意压缩内容的保证。

## 4. 未来影响

我的推断：memory 的第一层价值可能是运行连续性与可恢复性，而非回答新知识题。对你的 self-evolving memory，可把长期目标、已验证约束、短期执行状态分开，并对失败发现使用不易被摘要抹去的证据链。该持久基底可承载未来学习器，但本篇主要证明系统设计可行性，而非模型 continual learning 的算法创新。

## 5. Critical thinking

有界摘要必然面临信息取舍：哪些约束保留、哪些历史丢弃、谁拥有版本冲突裁决权？升级和每日人类决策也可能贡献大量可靠性，不能把所有成功归功于 memory。建议人为插入相互矛盾 journal、陈旧 checkpoint、关键反例与会话重启，比较层级文件与等 token 平铺记忆；记录遗忘率、恢复时间、错误传播与人工介入成本。记忆中“被记录”的结论仍须追溯到日志与 checkpoint，层级越高也不自动获得更高证据可信度。
