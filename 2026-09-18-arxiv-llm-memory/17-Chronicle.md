## 1. 做了什么

Chronicle 在模型调用、工具、路由等非确定性边界记录不可变 input/output envelopes。全量 replay 用历史输出替代全部边界，可稳定重现轨迹；cut-point replay 则只固定选定边界，其余用新代码执行，检查 bug 修复与行为回归。弱相关性在于它不设计记忆存储/召回，但能验证记忆更新是否造成历史事故重现。

## 2. 怎么做，实验如何设计

主要 benchmark 是六个自构造、三步事故，模型边界使用确定性的模拟 stubs。每个事故全 replay 重复 20 次，并比较坏代码、加保护的修复、30 个良性改动；另做 192 个 tool mutants。记录开销约 23 μs/边界，摘要 .008% 建立在假设 300 ms 模型调用上，不是该 benchmark 对真实在线供应商的通用测量。额外真实 Qwen3.5 4B CPU 测试 50 次，开启/关闭差约 91 ms，区间跨零。

## 3. 结论

六例 full replay 都零偏离，cut-point 测试对已知坏/修复代码正确 fail/pass。mutation 中捕获 51/192，而全部 stub 的 baseline 为 0/192；“捕获每个让已记录危险动作通过的 mutant”针对该 subset，不等于捕获全部 192。真实模型记录开销差的 CI 约 [-59,241] ms，只能说未检测到明显差异，不能证明开销严格为零。

## 4. 未来影响

我的推断：self-evolving memory 应随每条被采纳的 skill 保存可回放事故和回归约束。新记忆上线前，可固定历史模型输出而运行新路由/新权限检查，验证相同危险建议是否仍被拦截。这样经验不只是文字 lesson，而是有测试的行为合同。

## 5. Critical thinking

边界回放并不能自动处理外部数据库、时钟、环境副作用的一致性；工具输出固定后运行新代码，反事实状态可能与现实不匹配。当前不支持所有 streaming、并发工具等复杂场景；六例的断言也与事故共同设计，容易覆盖已知不覆盖未知。建议用真实长期 memory regression 事故、异步更新与 schema 迁移扩展，并设置不可预先见的 mutants。把“历史失败可复现”与“新版本未来安全”区分，前者是后者必要工具而不是充分证据。

## 6. 可信度判断

可信度 3/5：全文实现边界、六例设计、mutant 分母及真实模型辅助测量可核查。优点是 cut-point 操作比全 stub 更有修复测试价值；局限是小型自构造集、模拟模型、断言范围与外部状态问题。机构优先级高，但纳入理由是清晰的跨方向启发，不将其冒充直接的长期记忆性能改进。
