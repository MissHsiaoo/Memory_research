# 7. 排列任务中的扩散 LLM 设计空间

- 论文：[arXiv:2610.20635](https://arxiv.org/abs/2610.20635) · [官方 PDF](https://arxiv.org/pdf/2610.20635) · 本地 PDF：`2610.20635.pdf`
- 公告：2026-10-16；初次提交：2026-10-01。虽提交较早，仍仅因今日官方 `New submissions` 收录；不按提交日扩展窗口。
- 作者/机构：PDF 首页核验 Zhe Xu、Mingfu Liang 等；Meta。**机构优先级 P1**。
- 主题：diffusion LLM；permutation generation；recommendation reranking。**弱相关但具启发性**：扩散 LLM 的结构化输出设计。证据范围：全文 24 页。

1. **做了什么（论文证据）**：系统比较扩散 LLM 生成排列的三种参数化，而非提出通用文本记忆机制。
2. **怎么做与实验（论文证据）**：硬分配预测候选索引、软分配预测双随机矩阵、直接排序分数；把排列约束放在不同预测/解码阶段。使用三个 Amazon 推荐重排领域，候选集合大小 10/20，与受约束掩码扩散基线比较。
3. **结论（论文证据）**：一次函数评估时硬/软分配的 Recall@1 与基线可比；直接排序分数无需 Hungarian 或 Sinkhorn 即保证合法排列。增加评估次数并不总提高质量。
4. **未来影响（我的推断）**：扩散 LLM 的腐蚀方式、输出表示、目标函数和解码器应联动设计；这一原则可迁移到记忆条目排序，但本文未实测。
5. **Critical thinking**：重排任务非开放文本生成；应在更大候选规模、其他领域和端到端延迟下比较，明确约束满足与语义质量的权衡。
6. **可信度 3/5**：对照清楚、消融结构化；但证据局限于推荐排列，不足以宣称通用 dLLM 或记忆系统优越。
