# 24. TRACER：用工具调用轨迹检索大规模工具库

- 论文：[arXiv:2610.21267](https://arxiv.org/abs/2610.21267) · [官方 PDF](https://arxiv.org/pdf/2610.21267) · 本地 PDF：`2610.21267.pdf`
- 公告：2026-10-16；初次提交：2026-10-15。
- 作者/机构：PDF 首页核验 Tanish Kher、Sarvesh DK 等；Microsoft。**机构优先级 P2**（首页只写 Microsoft，不擅自称 Microsoft Research）。
- 主题：agent trajectory retrieval；tool-selection memory；scaling。**弱相关但具启发性**：轨迹作为工具先验。证据范围：全文 21 页。

1. **做了什么（论文证据）**：提出 TRACER，用过去工具调用序列构造 trie，并以经验与上下文先验混合排名下一步可用工具。
2. **怎么做与实验（论文证据）**：大工具库中只把少量候选暴露给 agent；在零售/电信混合 τ² 环境、六环境四模型等设置比较全库选择、token 开销与成功率。
3. **结论（论文证据）**：混合 τ² 设置中 GPT-5.4 工具选择准确率 +4.7 点，每步输入 token -80%，仅暴露 128 工具中的 5 个；自治执行成功率与全库相当而 token -61%。24 个模型—环境对中 21 个提高准确率。
4. **未来影响（我的推断）**：agent 经验可作为工具空间裁剪索引，而非自然语言知识；但工具路径记忆不代表用户/任务事实记忆。
5. **Critical thinking**：冷启动无轨迹时只能回退向量检索，论文指出此时准确率明显低；应测试工具注册表频繁变化、错误轨迹注入、长尾工具和维护成本。
6. **可信度 4/5**：多模型环境及完整执行/成本比较扎实；适用性受已有高质量轨迹和稳定工具目录限制。
