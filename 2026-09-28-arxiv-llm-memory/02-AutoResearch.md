# 02. AutoResearch at Production Scale

- arXiv：[2609.30541](https://arxiv.org/abs/2609.30541)
- 提交日期：2026-09-24；正式公告批次：2026-09-28（cs.LG new）
- 作者/机构（PDF 首页核验）：Aparajith Chandran 等；Amazon Books Core Recs Science
- 机构优先级：**S｜重点工业研究机构**
- 研究标签：self-evolving agent、agent memory、autonomous research、推荐系统
- 本地 PDF：[2609.30541.pdf](./2609.30541.pdf)

## 1. 做了什么

把“LLM 自动改训练代码、保留更优修改”的 AutoResearch 范式放到真实生产推荐中运行十二周，重点不是再报一个最好分数，而是总结长周期自进化代理的五类结构性故障：基础设施脆弱、记忆衰减、搜索方向停滞、迭代成本不对称和指标固着。

## 2. 怎么做、实验如何设计

框架用 prevent–persist–redirect 三原则：预防无效/危险试验，把实验结论和状态持久化，并用 critic 或人工 program.md 改变搜索方向。两个独立图书推荐表征系统共运行 220+ 次实验：System A 为多代理代码级搜索，单次 9–19 小时、60+ 次迭代；System B 为配置/架构搜索，单次 6–52 分钟、150+ 次迭代。相对手工基线，论文报告 Recall@6 提升 1.82×、coherence 提升 2.1×，并自动产生文本 fallback，使目录覆盖扩大 5.8×。

## 3. Conclusion

长周期自进化的瓶颈并非一次推理能力，而是跨实验记忆、恢复、预算和搜索治理。相隔约 760× 单次成本的两个系统仍出现相同故障，支持这些问题具有一定结构共性。

## 4. Future impact

对 self-evolving memory 的影响很直接：未来“代理记忆”必须保存失败原因、实验谱系、资源花费和停止条件，而不仅是成功 skill。它也提示 benchmark 应把数周运行中的恢复能力纳入评价。

## 5. Critical thinking

最强之处是长时间、真实成本和生产系统证据。主要因果问题是多项 scaffold 同时加入，难以把收益归因到特定记忆机制；两系统都来自同一推荐组织，也可能共享工程文化和基础设施。建议复现时冻结模型与搜索空间，逐项消融持久化日志、critic、checkpoint 和预算控制，并测试记忆污染后的恢复。

## 6. 可信度判断

**4/5。** 已阅读全文。220+ 生产级实验和跨三数量级成本的重复模式很有说服力；但任务域单一、组件消融有限，且完整内部系统难以外部复现。
