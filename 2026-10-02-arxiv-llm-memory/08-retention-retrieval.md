# 08 — What Should an Agent Remember? Disentangling Retention from Retrieval

- arXiv：[2610.00366](https://arxiv.org/abs/2610.00366)；[官方 PDF](https://arxiv.org/pdf/2610.00366)；[本地 PDF](./2610.00366.pdf)
- v1 提交：2026-09-30；正式公告：2026-10-02（北京时间）
- 作者/机构（PDF 首页核验）：Juli Huang；Stanford University
- 机构优先级：**A+，一流研究型高校**；研究标签：`agent memory evaluation` `retention` `retrieval`
- 证据范围：核读 8 页 PDF 的设计、实验与明确局限。

## 1. 做了什么

揭示记忆评估把“当初留没留下”与“查询时找没找到”混在一起时，容易把访问权限收益误报成检索算法收益。

## 2. 怎么做、实验如何设计

流式回忆环境交叉组合 retention 与 selection 规则，在每个条件下复用同 300 个随机种子回合。固定访问权限后，查询感知选择使必需事实召回 +15.5 个百分点（95% CI 12.8–18.2）；混合访问权限的对照显示 +68.7 点，其中 53.2 点归于访问差异。有限保留条件下观察到 319 次失败全由驱逐造成；SQuAD 复测检查自然语言情形。作者明确指出主要环境仅 10 个事实、2 次查询，属隔离机制而非真实多会话 agent。

## 3. Conclusion

有限容量的保留上限不能靠更好的检索器修复；记忆论文须分开报告写入和读取决策。

## 4. Future impact

可成为 memory benchmark 设计准则，避免强检索方法被“保留更多历史”这一混杂因素虚假抬高。

## 5. Critical thinking

**推断：** 小型合成环境可以清晰识别因果机制，但不反映噪声、含糊与跨会话更新。建议做真实用户历史的正交实验，固定存储预算和可访问集合，再比较选择器。

## 6. 可信度判断

**4/5。** 配对种子、置信区间、机制拆分和论文自陈局限增强可信度；绝对性能不宜外推到真实系统。
