## 1. 做了什么

论文证据：提出 context bank rot：单条示例各自正确，放在一起却遵循相互冲突的业务约定。将上下文记忆库质量从“每条是否正确”扩展到“条目之间是否一致”，并用 CAT 测试问题离记忆库多远时仍能受益。

## 2. 怎么做、实验如何设计

把 SQL 分解为与问题片段对应的语义决策，比较条目间的对齐、冲突与新颖性（ACN）；由人工校准的 LLM 裁判蒸馏快速评分器，构建 Bank Health Index。修复分单条审计与成对约定裁决两路。实验包含 BIRD 清洗后的微调、等量随机子集控制，以及 matched/opposite/mixed/no-context 四种示例条件；CAT-BIRD 与 CAT-Spider 按语义距离生成测试题，尝试匹配无上下文难度。

## 3. 结论

论文证据：清洗组相对同大小随机组四个 epoch 平均提高2.6个百分点，但这包含单条纠错贡献。120道配对题上同约定示例66.7%、相反约定53.3%，差13.3个百分点；混合示例接近无示例。151道库外计数题及470道自然分组题提供补充检验。CAT 中随着新逻辑占比增加，检索/微调收益缩小。不能把“自洽”视为“业务上正确”。

## 4. 未来影响

研究判断：对个人偏好、企业规范及 agent 技能库，应同时保存规则适用范围和冲突关系。检索准确率之外，值得增加“距已有记忆的泛化曲线”，识别系统是在复述还是迁移。

## 5. Critical thinking

关键假设是语义单元评分能代表真实决策距离。评分器主要覆盖 SQLite；裁判与生成器重叠、远距离样本较少、难度匹配依赖筛选，都可能影响曲线。微调每配置仅一随机种子，四个 epoch 不能算四次独立复现。建议在新 SQL 方言与真实业务变更上，固定正确性，只操纵约定冲突比例，比较带时间/作用域的记忆与直接删除冲突条目；同时用独立人工裁判核验。

## 6. 可信度判断

4/5。优点是把一致性与单条正确性拆开，提供控制实验、成对翻转检验和外部审计对照。局限是自动标注依赖、单种子、生成式测试的选择偏差；当前证据支持该场景中的机制，不足以证明任意记忆库的普遍因果效果。
