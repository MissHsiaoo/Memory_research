# 12｜Salesforce：能从 Agent 历史预测“何时压缩会伤害任务”吗？

- 论文：[arXiv:2610.08722](https://arxiv.org/abs/2610.08722)｜[官方 PDF](https://arxiv.org/pdf/2610.08722)｜本地 `2610.08722.pdf`
- 正式公告：2026-10-07；首次提交：2026-10-06（UTC；北京时间已为 10 月 7 日）。
- 作者/机构（PDF 首页）：Egor Pakhomov、Erik Nijkamp；Salesforce AI Research。机构优先级：S；标签：agent memory compaction、negative result；直接相关。

## 1. 做了什么

检验一个常见直觉：Agent 最近的行为是否足以决定下一次上下文压缩该延后还是执行。

## 2. 怎么做、实验如何设计

使用 TRACE 公开语料中 590 个 AppWorld 压缩边界的配对重放，从同一边界比较原始上下文与摘要后续动作的错误/重复负担。PDF 做预设对比、留出触发器及同边界重复实验；最好留出 AUROC 仅 0.66，对应重复实验标签的可达水平约 0.72；一个可解释规则避开 21% 有害边界，同时保留 84% 压缩机会。

## 3. 结论

目前的短期历史信号只能弱预测压缩伤害；预设的简单对比是宽区间零结果。作者明确指出公开语料无法严格检验最佳触发器在相同保留率下是否胜过 token 预算规则。

## 4. 未来影响（推断）

记忆压缩策略研究应报告边界级反事实结果，而不只看任务最终成功率；“会压缩”与“知道何时不该压缩”是两回事。

## 5. Critical thinking

单一 AppWorld/既有 harness 可能低估其他行为特征；也可能已经揭示预测上限。建议公开包含随机化压缩时机、重复标签和相同保留率预算的语料，再测跨任务/模型迁移。
