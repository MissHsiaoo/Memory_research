# 14｜FC-SWE：让编程 Agent 把失败验证转化为恢复学习

- 论文：[arXiv:2610.07898](https://arxiv.org/abs/2610.07898)｜[官方 PDF](https://arxiv.org/pdf/2610.07898)｜本地 `2610.07898.pdf`
- 正式公告：2026-10-07；首次提交：2026-10-06（UTC）。
- 作者/机构（PDF 首页）：Jia Liufu 等；NVIDIA、Tsinghua University。机构优先级：S；标签：agent experience learning、long-horizon coding；**弱相关但具启发性**：不是显式持久记忆系统。

## 1. 做了什么

把失败补丁与验证器反馈作为下一次完整恢复轨迹的条件，让多轮编程 Agent 不只依赖终局奖励。

## 2. 怎么做、实验如何设计

FC-SWE 在补丁失败后重置仓库到原始任务状态，再用失败补丁及验证反馈生成恢复尝试；轨迹局部奖励避免把后续成功错误记到早期失败补丁，active-set 优势估计只用实际执行的尝试。PDF 用 Qwen3.5-4B、SWE-agent、500 个 SWE-bench Verified 任务对比 GRPO；报告 Resolved@1 41.7% 对 38.9%，Resolved@2 52.8% 对 48.5%，并测更多测试时尝试。

## 3. 结论

在所测 verifier-assisted 编程任务，训练 Agent 如何从失败恢复，比把每次尝试当独立样本更有效；并非已证明外部记忆的长期收益。

## 4. 未来影响（推断）

自进化 Agent 记忆可保存失败诊断与恢复因果链，而不只收藏成功轨迹。

## 5. Critical thinking

验证器反馈可能不完整或错误，重置仓库也与真实连续开发环境不同。建议测有噪验证、跨仓库迁移、失败知识的检索价值和整体训练/推理成本。

## 6. 可信度：4/5

依据：已读 PDF 训练机制、500 题对照和具体百分比。优点是奖励归因清楚；局限是局限于编程及验证器辅助协议。
