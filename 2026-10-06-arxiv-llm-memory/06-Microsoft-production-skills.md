# 06｜从生产轨迹挖掘 Agent 技能：不存在通用最佳配方

- 论文：[arXiv:2610.05777](https://arxiv.org/abs/2610.05777)｜[官方 PDF](https://arxiv.org/pdf/2610.05777)｜本地 `2610.05777.pdf`
- 正式公告：2026-10-06；首次提交：2026-10-05。
- 作者/机构（PDF 首页）：Yue Ran Kang、Colton Mikolajczyk 等；MIT、Microsoft。机构优先级：S；标签：agent procedural memory、skill mining；直接相关。

## 1. 做了什么

系统比较如何从生产环境的 Agent 执行轨迹提炼可重用技能，而非提出一个在所有任务上均最优的单一记忆格式。

## 2. 怎么做、实验如何设计

论文交叉比较六种“轨迹证据 × 技能表达”配置，在 ThinkingBox-Bench 和 APEX-Agents 两个企业任务基准上测下游 Agent。ThinkingBox 中，工作流式技能相对 ontology 式约高 1.7 个百分点；取适中证据的 Goldilocks 配置相对只看成功轨迹约高 2.4 个百分点；但 APEX-Agents 不呈相同偏好。还做任务层面的配对分析。

## 3. 结论

技能抽取的证据选择和表示方式依赖任务分布；两个基准并未支持“一种配置通吃”的结论。作者也指出配对分析不足以预测未见任务的最佳配置。

## 4. 未来影响（推断）

实际记忆系统应把“从何种轨迹提炼、如何表达”视为可选择的策略，并维护任务条件下的选择证据，而非固定一套技能摘要器。

## 5. Critical thinking

生产轨迹可能含保密信息与偶然成功；成功标签也可能漏掉高质量的失败恢复。建议用时间切分、跨企业迁移和模型版本漂移实验，检验抽出的技能是否稳健；同时测无技能基线和技能注入导致的错误传播。

## 6. 可信度：4/5

依据：阅读全文方法、两套基准、配置对照和局限。优点是公开不一致的负面结果；局限是企业任务与托管模型变化使长期可复现性较弱。
