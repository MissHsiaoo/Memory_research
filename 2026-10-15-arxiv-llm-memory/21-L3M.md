# 21. L3M：可验证的自扩展 agent 运行环境

- 论文：[arXiv:2610.19591](https://arxiv.org/abs/2610.19591) · [官方 PDF](https://arxiv.org/pdf/2610.19591) · 本地 PDF：`2610.19591.pdf`
- 公告：2026-10-15；初次提交：2026-10-14。
- 作者/机构：首页核验 Carson Eisenach、Robert Joseph George 等；Amazon。**机构优先级 P2（强产业实验室）**。
- 标签：persistent agent state；self-extension；verifiable tools。证据范围：全文 31 页。

1. **做了什么（论文证据）**：提出 L3M harness/runtime，把 agent 的持久工作状态、协作与可验证能力授权整合。
2. **怎么做/实验（论文证据）**：状态与程序保留在 Git hub 中跨会话延续；作用域 capability token 传给每个工具、程序及子 agent；以 Lean 4 约束授权和可追溯变更，并在 TerminalBench 评估任务通过情况。
3. **结论（论文证据）**：未经针对性调参的安全工具配置，TerminalBench 通过率约为不安全 shell 配置的三分之二。论文重点是“有边界的持久能力”，非记忆问答 SOTA。
4. **未来影响（我的推断）**：agent memory 若持久化代码/状态，安全授权和可逆修改应成为记忆系统设计的一部分。
5. **Critical thinking**：安全限制和任务性能的折衷需量化；应测试跨用户隔离、撤销权限、恶意扩展代码及长时状态膨胀。不要把形式化局部授权等同于整个 agent 行为安全。
6. **可信度 3/5**：设计具体、可验证机制及实际基准；长期自改进收益和记忆质量未被直接测试。**弱相关但具启发性**。
