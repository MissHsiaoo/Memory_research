# 02｜Drafting Agents, Not Just Tokens：推测式递归自改进

- arXiv：[2610.16491](https://arxiv.org/abs/2610.16491)；[官方 PDF](https://arxiv.org/pdf/2610.16491)；本地 PDF：[2610.16491.pdf](2610.16491.pdf)
- 正式公告批次：2026-10-14；初次提交：2026-10-12。
- 作者：Xin Xu、Ke Cheng、Hao Wang、Yangru Huang、Yanghao Xiao、Zhichao Chen、Zhisheng Zhong、Xun Liu、Yi Li、Qian Li、Haibin Lv、Jun Zhang、Jie Jiang、Zhouchen Lin。
- 机构：Tencent AMS/Hunyuan、北京大学（PDF 首页署名）；机构优先级：**A｜重点产业研究机构/一流高校**。研究标签：self-evolving agent、递归自改进、验证、共享经验；与记忆系统为相邻主题。

## 1. 做了什么

**论文证据：**把推测执行思想从 token 生成推广到 agent 改进候选，让系统并行草拟、验证、接纳自我改进，减少串行进化的等待。

## 2. 怎么做、实验如何设计

**论文证据：**SpecRSI 使用 Verification-Aware Tree Search 与 Group Verification Optimization，针对不同候选改进进行树搜索和成组验证。实验覆盖 50 个科学任务的骨干模型—任务组合，并报告代码任务对 HGM 的比较。此工作重点是改进方案的搜索/验证，不是长期个人记忆的读写。

## 3. 结论

**论文证据：**论文报告在 50 个组合中优于 Janus；代码成功率 69.4%，比较对象 HGM 为 64.3%。这些是给定任务、骨干与验证预算下的结果。

## 4. 未来影响

**我的推断：**可将“记忆改写”当作待验证的改进候选，而不是每次反思后立即写入；多候选并行评估可能降低错误经验累积。

## 5. Critical thinking

**关键假设：**验证信号足够接近真实长期收益。**区别：**由单条迭代改进变成多候选推测与合并验证。**失败情形：**短时验证成功但产生记忆污染或长期任务退化。**建议：**在固定总 token/工具调用预算下，加测长期记忆保持、误改回滚率与验证器失效的鲁棒性。

## 6. 可信度判断

**3/5。**优点是跨任务比较和明确基线；局限是最关心的长期记忆安全与长期收益并未直接验证，且并行搜索的预算公平性需要持续关注。依据 PDF 方法与评测；机构强不自动提高证据分。
