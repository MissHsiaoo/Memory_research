# 15｜LatentRemedy：多智能体非前缀 KV 复用的潜在补救

- arXiv：[2610.18014](https://arxiv.org/abs/2610.18014)；[官方 PDF](https://arxiv.org/pdf/2610.18014)；本地 PDF：[2610.18014.pdf](2610.18014.pdf)
- 正式公告批次：2026-10-14；初次提交：2026-10-13。
- 作者：Zhiwei Chen、Zhongtao Rao、Waikit Xiu、Yuxiang Zhang、Shuting Cui、Jian Chen、Tianxiang Zhao。机构：香港科技大学（广州）、Microsoft（PDF 署名为 Microsoft，**不能擅自升级称 Microsoft Research**）、香港大学；机构优先级：**A｜一流高校/重点产业合作**。研究标签：latent memory、KV cache、multi-agent、上下文复用。

## 1. 做了什么

**论文证据：**处理多 agent 共享前缀以外上下文块时的 KV 缓存失配：直接复用快，但会严重损害下游任务质量；提出 LatentRemedy。

## 2. 怎么做、实验如何设计

**论文证据：**在复用 KV 块后插入任务条件化潜在 token，并从全量 prefilling 的教师行为蒸馏；比较直接复用、全量预填与补救法的质量和首 token 延迟。全文局限：只评测三个规模的 Qwen3 模型，单 RTX 5090、共享块最长 4096 token；跨家族、更多硬件/长度尚未验证。

## 3. 结论

**论文证据：**论文指出朴素复用可造成最高约 90% 的性能跌落；LatentRemedy 在冲突任务上恢复表现，同时 TTFT 接近直接复用。最高跌落是特定测试条件，不是通用风险率。

## 4. 未来影响

**我的推断：**agent 系统的计算型“记忆复用”需要上下文适配层，不能因为 KV 形状相容就认为语义相容。

## 5. Critical thinking

**关键假设：**少量潜在 token 能修补任意任务条件变化。**区别：**不重算整段上下文，而学习局部补救。**建议：**跨模型/硬件、4K 以上共享块和频繁切任务负载测端到端吞吐与错误恢复。

## 6. 可信度判断

**3/5。**有明晰的质量—延迟权衡与对照；模型家族、硬件、共享长度有限。评分依据 PDF 方法/实验/作者局限，与机构标签分离。
