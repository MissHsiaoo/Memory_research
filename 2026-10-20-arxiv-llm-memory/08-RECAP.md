# 8. RECAP：长期 agent 何时该遗忘

- **arXiv**：[2610.22897](https://arxiv.org/abs/2610.22897)；[官方 PDF](2610.22897.pdf)
- **提交日期**：2026-10-16（v1）。
- **作者/机构**：Chenle Chen 等。PDF 首页核验：UCLA、上海交通大学、Arizona State University、东方理工大学。
- **机构优先级**：P1（多所研究型大学）。**研究标签**：agent memory；上下文压缩/删除；风险控制；paired intervention。
- **证据范围**：完整 PDF，32 页；文件可解析。

## 1) 做了什么

提出 RECAP，研究同一失败记录在不同执行阶段可能从有用变成冗余，或反过来；在 KEEP 全历史基线上比较保留、压缩、移除的后续任务收益与成本。

## 2) 怎么做、实验如何设计

方法结合配对状态/seed 的上下文干预，比较成功率及 continuation prompt cost；只从当前执行前缀推断 failure block 与当前状态关系以提议编辑；再用独立任务包在“有害干预风险”和“无正收益风险”约束下认证策略。五 seed 纵向案例固定同一 failure block 与其 summary，在不同 execution point 重测；跨五个 backbone 做 paired success-saving 估计。

## 3) 结论

作者报告：固定失败摘要早期压缩会失败，后期可成为省成本编辑；Hunyuan-A13B 上编辑 43.24% checkpoints，同时观测成功率与 KEEP 相同（91.89%），平均 continuation prompt 少 4,619.8 tokens（2.13%）。

## 4) 未来影响

将遗忘视为有风险、需情境判断和独立验证的动作，而不是单纯按 recency/长度预算删除；可指导长链任务对失败轨迹实施阶段性压缩。

## 5) Critical thinking

- **关键假设**：匹配状态和种子能构造有效反事实；prefix-only 执行关系能预测何时记忆块对下一步有用。
- **差别**：显式测“同一记忆块在不同阶段”的时间变效用，并做独立 policy certification，而非固定摘要或基于 token 限额机械遗忘。
- **风险**：报告的 2.13% token 降幅有限；成对差异、任务束选择及风险约束参数可能影响稳定性。五 seed 案例仅是机制示例而非普遍规律。
- **后续建议**：预注册非劣效界限和风险阈值；扩展到多种 memory 类型、冲突/过期事实及长周期偏好；计入延迟、存储与后续错误修复成本。

## 6) 可信度判断

**3.5/5。** 依据：全文给出配对干预、独立策略认证、多 backbone 与明确数字。优点是对 KEEP 做执行级比较且呈现边界条件；局限是特定任务/seed 上的匹配推断，通用用户记忆和长期部署的外部效度还不足。
