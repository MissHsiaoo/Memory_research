# 03｜VERSE：有执行验证的自进化 Agent Harness

- 论文：[arXiv:2610.02616](https://arxiv.org/abs/2610.02616)｜[官方 PDF](https://arxiv.org/pdf/2610.02616)｜本地：`2610.02616.pdf`
- arXiv 正式公告：2026-10-05；首次提交：2026-10-02。
- 作者/机构：首页核验 Zekai Wang 等；MIT、Amazon。
- 机构优先级：S；标签：self-evolving agent、工具/技能记忆、程序验证。关联性：直接。

## 1. 做了什么

VERSE 不只修改被优化 Agent 的 prompt、工具和流程，还让优化器迭代自己的提示、技能、工具、hook 与笔记；模型权重保持不变。

## 2. 怎么做、实验如何设计

核心闭环是草案编辑、执行测试、失败回放、受扰动步骤检查，再跟踪修复与回归。PDF 用不交叉的训练/验证/测试任务，在 SWE-rebench 的 108 个同分布 Python 测试任务与 107 个较新跨语言任务上对照四种 harness 优化器；每轮三候选、六轮演化，验证调用占执行次数 2–7%。最佳验证集选择的 harness 达 42.3%/37.7%，强基线为 39.2%/29.3%；论文亦说明方法间总计算量并非完全一致。

## 3. 结论

自进化优化器只有配合执行验证才稳定获益；仅让优化器自由改写自身，不能据此预期可靠提升。

## 4. 未来影响（推断）

对可持续 Agent 记忆的启示是将失败修复经验变成经回归测试认证的技能和工具版本，而不是任意累积文字经验。

## 5. Critical thinking

关键因果问题：收益来自“自我改写”还是额外验证计算？文中总 compute 有差异，应做严格等预算实验。另需测试技能膨胀、版本冲突、测试集泄漏、优化器把验证规则本身改坏的情形；建议对每轮改动保存可回滚 diff 与外部不可变验证器。

## 6. 可信度：3/5

依据：已核 PDF 训练协议、样本数、核心表和计算差异。优点是有不交叉测试及多语言 OOD；局限是单次演化运行、测试估计误差和计算预算混杂，故未给高分。机构等级不影响此分。
