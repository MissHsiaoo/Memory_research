# 14｜Sentry：失败发生时才注入可验证恢复经验

- 论文：[arXiv:2610.02994](https://arxiv.org/abs/2610.02994)｜[官方 PDF](https://arxiv.org/pdf/2610.02994)｜本地：`2610.02994.pdf`
- arXiv 正式公告：2026-10-05；首次提交：2026-10-02。
- 作者/机构：首页核验 Changxiu Ji 等；Stanford University。
- 机构优先级：A+（顶尖研究型高校）；标签：agent memory、test-time learning、条件经验检索。关联性：直接。

## 1. 做了什么

Sentry 把失败教训放在 Agent 上下文外：先检测当前失败，再取相似教训指导修复，验证成功后才把新教训写回；避免整本 playbook 常驻上下文造成误触发。

## 2. 怎么做、实验如何设计

外部失败管理层进行检测、匹配检索、无任务奖励的恢复判定和门控写入。PDF 在 WebShop、Mind2Web Replay、SWE-bench Lite、AppWorld 比较运行时干预和上下文演化基线；部分对照使用每基准 100 任务，SWE-bench Lite 50 任务。作者报告相对最强运行时基线平均提升 37%，与可比的上下文演化基线在两基准平均提升 39%；全 playbook 常驻会降分。

## 3. 结论

失败知识有触发条件；选择性暴露和事后验证比无条件追加上下文更重要。

## 4. 未来影响（推断）

长期 Agent 记忆可从被动“总结历史”转向事件触发型的恢复政策库，并为每条经验附上适用情境与验证证据。

## 5. Critical thinking

检测器与验证器都用同源模型，会有共同模式错误；论文局限也承认 playbook 会变得重复或过于具体。应测试误报/漏报、遭恶意工具输出污染、长期增长后的检索质量及外部验证器独立性。Mind2Web Replay 的指标不可与官方 step-wise 指标直接比。

## 6. 可信度：4/5

依据：已查 PDF 四基准实验、基线、消融及明确局限。优点是核心假设有“常驻 playbook”反证；局限是模型与任务范围有限、自动验证可靠性有待扩展。
