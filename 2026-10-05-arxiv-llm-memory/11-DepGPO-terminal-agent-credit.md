# 11｜DepGPO：沿终端命令依赖链分配强化学习信用

- 论文：[arXiv:2610.03634](https://arxiv.org/abs/2610.03634)｜[官方 PDF](https://arxiv.org/pdf/2610.03634)｜本地：`2610.03634.pdf`
- arXiv 正式公告：2026-10-05；首次提交：2026-10-02。
- 作者/机构：首页核验 Yu Li 等；Huawei Noah's Ark Lab、Southeast University。
- 机构优先级：S；标签：agent continual learning、轨迹经验、信用分配。关联性：邻近，弱相关但具启发性。

## 1. 做了什么

DepGPO 不把终端 Agent 的成功或失败平均分摊到所有步骤，而是追踪命令读写的依赖关系，强调真正通向最终验证对象的操作。

## 2. 怎么做、实验如何设计

从执行日志建命令依赖图，从任务验证器读取的资源反向追溯，给相关写入及其支持读取重分配轨迹优势。PDF 用 Qwen3.5-9B、Qwen3.6-27B，分别配 SETA/TMAX 数据，在 Terminal-Bench 2.0/2.1 测 pass@1；与 SFT、GRPO、DAPO、DPPO、GiGPO、GraphGPO 比较，并做消融和三轮评测均值/标准差。表中 DepGPO 在四种模型—数据配置和两个测试集上均优于所列基线。

## 3. 结论

执行依赖是比均匀轨迹回报更有结构的学习信号；论文展示了终端任务上的性能与训练稳定性提升。

## 4. 未来影响（推断）

经验记忆若保留“哪个动作依赖哪个证据并导致何种结果”，可能比只保存成功/失败总结更利于 Agent 自我改进。

## 5. Critical thinking

文件和命令依赖能被显式记录，但开放网页、多人协作与隐含因果链未必如此。验证器只看最终文件也可能错过关键探索步骤。建议做依赖图漏边/伪边扰动、同计算预算对照及跨工具迁移；不能把关联路径直接等同真实因果。

## 6. 可信度：3/5

依据：已读 PDF 算法、两代 Terminal-Bench 表与消融描述。优点是明确机制及多基线；局限是结构化终端环境较窄，依赖追踪可靠性在开放 Agent 中未证实。
