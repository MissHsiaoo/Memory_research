# 15｜Spurious Tool Use: When RL Agents Learn the Wrong Reason to Act

## 1. 做了什么

研究agent通过RL学会调用工具时，是否学到正确的理由。即使最终答案正确，工具选择也可能依赖与任务无因果关系的标签或格式；这些捷径若被写进经验记忆，会变成反复执行的坏习惯。

## 2. 怎么做，实验如何设计

受控训练集从Natural Questions和DeepMath各取500题，共1000题，只给其中一类加入与工具有语义联系的无关cue，例如web index标记、reference标签或Python cell头。用VERLTOOL及GRPO训练，评测时对同一道题构造有/无cue配对，并在2Wiki、GSM8K测试分布外泛化。还交换cue和任务的对应关系，以分辨语义先验与简单统计关联。

表1中，WEB INDEX cue在GSM8K令搜索调用率从0.9%到40.1%，差39.2个百分点，不是相对增加39.2%。相反，代码cue未导致同等规模的虚假Python使用，表明效果不对称。改进方法用GPT-5 Nano根据题目、工具类型与调用输入判断必要性，对不必要调用每次罚0.5；在所测搜索设置中cue差异接近消失。

## 3. 结论

直接证据：答案级奖励不足以确保工具选择依据可靠，cue捷径与任务能力/语义先验有关。必要性奖励可抑制特定捷径，但不等于从根本上解决所有无效工具调用，也不说明所有相关cue都会产生相同效果。

## 4. Future impact：未来影响

我的推断：self-evolving memory的更新标准不能只看“这次最后成功了”，应检查成功是否依赖无关环境特征。可给每条程序性记忆附反事实验证：移除外观标签、更换工具名或改变表述后，策略是否仍合理。与个性化结合时也要防止将用户措辞误认成真实偏好。

## 5. Critical thinking：批判性分析

“一个有能力模型不用工具就能答出”不是客观固定的必要性定义；小模型可能合理需要工具来校验，大模型judge却判为不必要。数学搜索一律无用的任务假设，也不适合需要最新定理/来源的现实问题。密集处罚可能减少合理核查，只看调用率下降不够，必须同时看正确率、校准与成本。

建议加入确实必须外部检索的数学题、确实需要计算的事实题；由程序或独立专家构建必要性标签，比较简单调用成本惩罚和语义必要性惩罚，并多种子测量cue效应。

## 6. 可信度、优点与局限

3.5/5。优点：配对反事实、对称/交换cue控制让捷径因果关系比较清楚，能直接启发记忆质量审计。局限：训练规模小、工具只有少数类型、judge必要性有主观性，机制推广到真实长任务尚未充分建立。已读数据构造、方法和主表，未重复RL训练；与memory的联系是研究拓展而非论文已有实现。
