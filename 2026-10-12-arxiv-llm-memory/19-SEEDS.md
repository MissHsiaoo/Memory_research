# 19 SEEDS：决定哪些检索证据进入推理状态

- 论文：[arXiv:2610.12932](https://arxiv.org/abs/2610.12932) · [官方 PDF](https://arxiv.org/pdf/2610.12932) · [本地 PDF](2610.12932.pdf)
- 日期：**2026-10-12 正式公告**；2026-10-09 提交。
- 作者：Jiajin Liu、Chenxi Xu、Dongzhe Fan、Yuanfu Sun、Qiaoyu Tan。机构：New York University、New York University Shanghai（PDF 首页核验）。
- 机构优先级：B（一流研究型高校）；研究标签：retrieval-memory、search agents、evidence admission。

1. **做了什么｜论文证据：**将检索结果“是否进入代理推理上下文”定义为独立的 evidence admission 决策，提出 SEEDS。
2. **怎么做、实验如何设计｜论文证据：**先看候选文档轻量预览，再依据当前推理状态选任意子集及数量进行全文读取，而非固定 top-k/前缀；可直接附加 ReAct、Search-o1，也可继续学习优化。在 9 个知识密集 QA 基准上测本地语料和实时 Web 搜索的答案质量与完整文档消费量。
3. **结论｜论文证据：**报告更高搜索效果、更少全文证据消耗，并能选到排名前缀之外的有用材料；它是检索/工作记忆入口策略，不是持久个人记忆系统。
4. **未来影响｜我的推断：**代理记忆可把“何时允许证据影响状态”作为安全与效率控制点，而不只是优化向量检索排序。
5. **Critical thinking｜我的推断：**预览若失真或遗漏关键事实，选择器可能系统性拒绝反证。建议构造低排名决定性证据、诱导性摘要与时效冲突，报告误拒率、回答校准和总 token/时延。
6. **可信度：4/5。**依据：核查九基准、两类搜索环境及质量/消耗指标；优点是明确可检验的新决策点，局限是预览质量和 live Web API 不稳定影响复现。
